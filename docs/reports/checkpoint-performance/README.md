# 存檔 CPU 優化（2026-10-04）

## 基線與範圍

基線 develop `031f232`。Godot 4.7.2、macOS 原生 headless，同一台電腦。`tools/bench_checkpoint.gd` 讀現行 campaign.tres，種子 742601，完整 20 區、72 資源節點；三輪各 100 次 capture／restore，表列各輪均值的中位數。原始結果見 before.log／after.log。

| CPU 工作 | 修改前 µs | 修改後 µs | 降幅 |
| --- | ---: | ---: | ---: |
| 存檔資料擷取 capture | 2,053 | 558 | 72.8% |
| 還原與有效性驗證 restore | 9,932 | 8,155 | 17.9% |
| 兩項中位數合計 | 11,985 | 8,713 | 27.3% |

不包含 JSON、檔案 I/O、繪圖、GPU，也不是原生完整幀率或手機測試。基線第三輪其他操作也變慢，代表有系統雜訊，故不採最快輪數值，也不宣稱整體 FPS 提升。

## 原因與修改

- 每個同類型資源節點都重新建立完整欄位描述；改為每個 codec 按 Script 快取固定欄位名稱。快取只有固定存檔圖的型別，不保存居民、掉落物或遊戲狀態，隨 codec 釋放。
- `_copy_fields` 原先深拷貝所有預設容器後，只用來查型別／欄位，再拷貝真正保存值。型別檢查改用暫存唯讀參照。
- 正式擷取與寫入還原物件仍深拷貝，所有形狀、範圍、未知版本與損壞資料檢查保留。玩法、畫面、存檔 v14、存檔頻率不變。
- 快取只適用這個封閉存檔圖的固定 GDScript 欄位；未來若新增動態 `_get_property_list` 或支援執行中熱換腳本，須重新評估，不作為任意物件通用序列化器。

## 驗證

- 修改前先補副本隔離回歸：多次 capture 讀到新值但不改舊快照；還原旅程不共用原旅程／packet 容器；換地圖設定後正確讀取、損壞巢狀欄位仍拒絕、拒絕後舊旅程可讀。
- 修改前與修改後核心均 2,405 項斷言通過。效能重構沒有新增玩法，既有行為期望值未修改。
- `soak_current.gd` 使用現行完整地圖設定，依既有 soak 工具加速 30 分鐘、七個時點存讀。會補血清怪維持壓力，不代表自然遊玩平衡；七次存讀全部通過（見 soak.log）。暖機後 Godot static memory 43.9–44.1 MB、物件數 1,754；30 分鐘時 44,013,311 bytes，未觀測到持續累積。這不包含 GPU／瀏覽器記憶體。
- 完整 `tools/check.sh` 七次存讀全部通過（見 soak.log）。暖機後 Godot static memory 43.9–44.1 MB、物件數 1,754；30 分鐘時 44,013,311 bytes，未觀測到持續累積。這不包含 GPU／瀏覽器記憶體。尚未 iPhone、Android、Windows 真機量測或實際原生 FPS 驗證。
