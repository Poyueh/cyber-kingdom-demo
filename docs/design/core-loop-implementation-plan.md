# Cyber Kingdom 核心循環實作計畫

日期：2026-10-18。狀態：規格已確認，實作未開始。依據：[核心循環優化規格](core-loop-optimization.md)。本文件是未來工作清單，不代表已新增功能、已測過新玩法或已發布版本。

本次只保存規格、工作順序和驗收方法。收到後續實作指示才進入 M0；不先建立功能程式、改 Resource、改輸入、改存檔格式、改美術或打包發行。

## 1 實作邊界與現況

以 v0.0.53 為現況基準。核心試玩建立獨立的新紀錄及明確模式／規則標記，共用現有戰役、場景和輸入系統；不複製整套遊戲或重建七星內容。首階段不把新規則套入舊旅程。正式旅程整合須根據核心試玩結果再審訂。

| 項目 | 已有內容 | 本次需要補足或改變 |
| --- | --- | --- |
| 引導 | campaign_guide 依狀態給建議，spirit_guidance 有固定活動期限 | 持久化教學階段，以真實採集交付推進；取消核心模式的超時退場 |
| 日夜 | campaign_clock 與夜襲時鐘 | 只對首夜加入備戰門檻，工作模擬持續；自主段恢復正常日夜 |
| 付款 | investment_hold 已鎖定長按目標、保留續填／退款 | 驗證重疊候選與點按歧義，使焦點、用途、付款和完成回饋一致 |
| 防線 | frontier_defenses 有左右位置、擴張與避難點 | 指定數量、塔位配置、前往／到位狀態、失效位置處理 |
| 居民 | 弓兵可狩獵及射擊；現行感受式旅程未受威脅時夜間仍可工作 | 核心模式依路程提前回防、夜間守位、駐塔不狩獵 |
| 戰鬥 | 連斬、體力、強制喘息與站定再衝刺 | 核心模式普攻免費、耗盡一般跑、移動恢復與再啟動 |
| 保存 | 戰役快照 v21、星球封套、紀錄目錄及續玩 | 持久保存兩種準備點、教學／配置／模式與完整還原 |
| UI | 晶袋、圖示、情境提示與少量三語說明 | 小型晶數、情境體力、用途／成本、完成分層與配置操作 |
| 關卡 | 星球分區、近郊資源、晶巢與夜襲 | 核心試玩受控骨架、兩段節奏、可靠的可行收入與返回距離 |

玩家回報的「背後生成」和「投晶對象混亂」先建立可重現場景，不能在無證據時把感受寫成已確認的某個程式缺陷。既有測試作為回歸基線，新的核心規則以模式專用案例驗證，不直接改掉所有舊期望值。

### M0 基線與模式

- [ ] 從乾淨 develop 建實作分支；確認最新已發布基線，不假設文件編寫時的分支永遠最新。
- [ ] 保存既有測試、操作錄影及典型新舊存檔，建立實際輸入下的付款混淆／敵人接近案例。
- [ ] 確認核心模式入口、獨立紀錄、規則標記及完成狀態；不覆寫既有旅程。
- [ ] 先測試模式隔離、未知標記拒絕與舊紀錄不被重新生成，再接最小模式設定。
- [ ] 繪出持久化欄位與準備點封裝，決定版本遷移與上限；原有快照使用反射，不能隨意加 session 欄位。
- [ ] 將所有待調參數集中於 Resource，確保日後可在 Inspector 調整。

### M1 第一次收入

- [ ] 以實際工作來源識別採集收入；撿回丟晶／贈晶／寶箱不能誤過關。
- [ ] 按點火、招募、領錘、委託、作業、交付分段；允許先行完成，不重發。
- [ ] 建立功能開放狀態及略過／重新顯示教學；略過不繞過首次收入解鎖，不以播放完動畫或超時作完成條件。
- [ ] 接入首夜尚未放行的準備狀態，保持居民工作運行並停止夜襲強度累加；M4 再接完整放行與預警。
- [ ] 先呈現一個目標；第一次交付連結工匠動作、晶體與晶袋數量。
- [ ] 驗證工作範圍不依賴尚未能付款的牆，缺晶時有真實收入或重新開始出口。
- [ ] 最小測試涵蓋慢速操作、接單未交貨、提前完成、略過、存讀延續。

### M2 付款與騎士操作

- [ ] 高亮、行動、用途、已付／總價來自同一份互動結果；不要兩次掃描得出不同目標。
- [ ] 先重現 NPC 經過、雙物件相近、觸控連點、長按完成後未放開、離開和退款的案例，再修正缺口。
- [ ] 補上器具、施工、採集與配置各自的完成回饋；同一筆費用只扣一次。
- [ ] 實作核心普攻零體力花費；保留連斬、原地／踏斬、收招與碰撞規則。
- [ ] 衝刺耗盡轉一般跑、移動中恢復、可再啟動；去除核心模式的強制喘息及連續站定需求。
- [ ] 晶數和情境體力條接真實狀態；測試持續按住衝刺的臨界抖動及姿勢銜接。
- [ ] 檢查配置快捷鍵與 InputMap，手機功能入口不遮擋攻擊／付款；三語文字先用實際尺寸驗證。

### M3 守軍配置

- [ ] 定義同側一般防線與固定塔位的目的地、容量和人員識別，避免雙重配置。
- [ ] 實作增派、撤回、改派；顯示已指定／前往／到位，不花晶、不瞬移。
- [ ] 白天只在所屬側與合法範圍狩獵；以返程路程／速度／餘量提前回防。
- [ ] 夜間守位優先於打獵、撿遠晶與追敵；駐塔者日夜不外出。
- [ ] 人員失職／死亡、塔毀、重建、位置不通和快速改派有明確結果。
- [ ] 以可見角色路徑驗證回防，不只斷言目的地數字改變。

### M4 首夜與第一準備點

- [ ] 準備門檻讀收入、建築和到位事實，未付款完／未施工完／人在路上都不能假就緒。
- [ ] 準備期間工作照常、日夜強度不增加；門檻放行後只播一次預警，不反覆重置。
- [ ] CP1 在收入與服務開放完成、主要投資前同一步驟捕捉；檢查仍有可行備戰收入。
- [ ] 首夜單側基準波；模擬騎士零攻擊時最低配置仍能守住，再測真人的支援價值。
- [ ] 依真實事件呈現失敗；淡黑後再提供重試與返回。
- [ ] 準備點先驗證再替換，含亂數、待到達敵人、居民持晶與待施工；錯誤不覆寫原檔。
- [ ] 重啟後重試、連續重試、載入時按住輸入、失敗中的自動存檔都不能污染 CP1。

### M5 第二次自主運用

- [ ] 首夜結束判定包含本波未到達／未清除敵人；進入自主段前建立 CP2。
- [ ] 取消逐步指定投資，保留用途、晶數、配置和來襲資訊；日夜不再等備戰門檻。
- [ ] 近郊地標、粗略補給提示、短遭遇與回程預警構成一段完整往返。
- [ ] 以一般跑速驗證合理返回路徑，不要求耗盡衝刺才能趕回。
- [ ] 實際計算並跑通增兵／加固／先收入等不同投資路徑；看懂代價且不只有唯一答案。
- [ ] 第二次可左右錯開，確保有可用防線位置且不用騎士同時兩邊代守。
- [ ] 營火存活且本波真正結束才呈現成果；完成旗標與七核通關分開。

## 4 測試策略

新增規則與 bug 修正遵循先重現失敗、再做最少實作、最後整理。不能靠改測試期望值把舊規則也改掉。單純畫面尺寸與動畫不寫鏡像單元測試，使用原生場景與實際輸入觀察。

| 驗證層 | 主要檢查 | 證據 |
| --- | --- | --- |
| 規則 | 教學事件、日夜門檻、經濟、配置、回防、衝刺、攻勢結束 | 核心測試的失敗／通過紀錄 |
| 確定性 | 同 seed 同輸入結果一致；存讀後接續推進與連續推進一致 | 狀態比較，包含亂數與延遲工作 |
| 保存 | CP1／CP2、連續重試、重啟、損壞、未知版本、v21 舊紀錄 | 實際序列化往返與拒絕覆寫案例 |
| 場景 | 付款焦點、真實交付、角色到位、預警和失敗回饋 | 原生畫面、錄影與實際輸入 |
| 平台 | 桌面鍵盤／手把若既有支援、iPhone／iPad 觸控與安全區 | 實機型號與測試結果；未測明列 |
| 成品 | 匯出後入口、翻譯、模式、保存與重試 | 正式包 smoke 與關鍵流程 |
| 真人 | AC25–26 與完整第一／第二段 | 匿名觀察表，不靠開發者口頭救場 |

每個里程碑先跑影響範圍內的測試；完整可交付候選執行 `bash tools/check.sh`，檢查 SCRIPT ERROR 和 ERROR，不能只看退出碼。新增核心案例加入完整檢查，避免只留本地臨時腳本。已通過後不因時間允許而無理由重複所有測試。

### 三種必要路徑

1. 引導新手：逐步完成、沒有額外贈晶、首夜不親自攻擊也能通過。
2. 自主玩家：略過提示、自由順序、不同投資仍能完成，必要資訊可查。
3. 出錯玩家：付款中斷、缺晶、守軍失效、探索太晚、戰敗及重啟後重試，均有明確結果和可恢復路徑。

## 5 數值調整順序

1. 先算可行性：費用／收益／工作範圍沒有死結，最低防線確實守得住。
2. 再量測時間：步行、等待、作業、施工與戰鬥各占多少，總體接近 10–15 分鐘。
3. 再比較決策：增兵與加固等選擇都有用途；不靠唯一解或免費補晶保證成功。
4. 最後調手感：衝刺恢復、提示淡出、付款節拍與工作動畫，不能改完美術就當作可理解。

每次調整記錄原因、修改參數、玩家可見差異與驗證結果。過慢先找空轉來源；過難先檢查可讀性與回防，避免直接加錢或砍敵人掩蓋問題。

## 6 風險與處理

| 風險 | 處理與驗收責任 |
| --- | --- |
| 第一夜永遠不開始 | 顯示欠缺的真實準備、保證合法資源與居民、測試略過教學；不以硬倒數突然攻擊補洞 |
| CP1 已經無法修正決策 | 捕捉於主要支出前，保留可用收入來源；測試資源不足及異常邊界 |
| 重試複製資源或混入上一輪效果 | 準備點不可變、完整驗證與一次替換，清除輸入／純呈現狀態 |
| 士兵數字正確但人不在 | 分離指定／前往／到位，門檻和戰鬥使用真實到位 |
| 普攻免費後騎士包辦所有防守 | 不靠重新偷偷加體力費平衡；測試範圍、收招、敵人配合與兩側安排 |
| 可讀性靠大量文字堆出來 | 一個情境一個主要提示，名稱＋用途＋費用；三語及手機原生驗收 |
| 舊旅程突然套新規則 | 模式與設定版本保存，舊測試保持舊預期；只對新核心紀錄啟用 |
| 核心模式成為另一套難維護遊戲 | 共用現有規則入口，新增具體小模組；不要拷貝整份 campaign_session |
| 教學人人過，但自主段仍不懂 | 真人驗收以第二段決策與理解為主，第一夜只算教學通順 |

## 7 文件與未來發布
